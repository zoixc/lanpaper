# Lanpaper — варианты обновлённого интерфейса

Файлы: `design/prototypes/` · один общий дизайн-слой на всех.

---

## Как посмотреть

```sh
python3 design/preview.py        # затем открыть http://localhost:8000
```

Корень отдаёт стенд с вариантами (скрипт сам редиректит с `/`), статика
раздаётся из корня репозитория, поэтому шрифты и иконки приложения на месте.

| Файл | Что это |
|---|---|
| `prototypes/index.html` | оглавитель: четыре варианта, палитра, переключатель темы |
| `prototypes/a-library.html` | Вариант A «Библиотека» |
| `prototypes/b-streams.html` | Вариант B «Потоки» |
| `prototypes/c-console.html` | Вариант C «Пульт» |
| `prototypes/d-sections.html` | Вариант D «Разделы» — доработанный «вариант 2» |
| `design/preview.py` | локальный статический сервер для стенда |
| `tokens.css` | цветовые токены, тени, радиусы, типографика (светлая + тёмная) |
| `prototypes/shared.css` | общие компоненты: кнопки, поля, меню, бейджи, тосты, шторка, панель деталей |
| `prototypes/variant-*.css` | только то, что специфично для варианта |
| `prototypes/proto.js` | поведение: фильтры, поиск, сортировка, меню, выбор, табы, темы |
| `prototypes/media/` | 5 сгенерированных обоев для наполнения макетов |

Всё статическое: кликайте, вводите в поиск, открывайте меню, переключайте темы
(кнопка справа сверху или клавиша `T`), меняйте ширину окна. Никаких сборок.

## Сравнение

| | A «Библиотека» | B «Потоки» | C «Пульт» | D «Разделы» |
|---|---|---|---|---|
| **Кому** | домашний сервер, 10–60 ссылок | 100+ ссылок, много плейлистов | цифровые вывески, киоски | те, кому нужен явный каркас разделов |
| **Плотность** | низкая: крупные превью | высокая: строка = ссылка | средняя: канал + панель | средняя: карточка + сайдбар |
| **Каркас** | центр + выезжающая панель | фиксированный сайдбар | карточки + постоянная панель | фиксированный сайдбар разделов |
| **Что в покое на карточке** | имя, мета, бейдж доступа | те же данные в строке | статус, файл, ротация, показы | имя, мета иконками, бейдж доступа |
| **Смена файла** | hover → «Заменить» | ⋯ → «Заменить файл» | кнопка в панели | кнопка «Заменить» на карточке |
| **Версии / плейлист** | вкладки панели | ⋯ → пункты меню | очередь и версии в панели | ⋯ → пункты меню, вкладка «Версии» в панели |
| **Массовые операции** | ✓ панель | ✓ строка в шапке | — | ✓ панель |
| **Мобильный** | 2 колонки, шторка | карточки-строки | лента, шторка | бургер → выдвижной сайдбар |
| **Риск** | при 200 ссылках много листать | «производственный» вид | избыточен при малом числе экранов | сайдбар «съедает» 244 px на ноутбуке |

**Как выбирать.** A и D — про одно и то же, «ссылки как галерея»; разница в том,
насколько явно интерфейс показывает свои возможности: D заметнее для новичка,
A спокойнее для ежедневной работы. B — если ссылок действительно сотни.
C — если продукт используют как систему для экранов, а не как файловый склад.

## Вариант D: что исправлено в присланном макете

«Вариант 2» делает половину правильных вещей, поэтому D — это он же, но
доведённый. Построчные отличия:

| В «варианте 2» | В варианте D | Почему |
|---|---|---|
| Сайдбар смешивает разделы и действия: `Links / Gallery / Settings / Upload / API Docs / About` | Разделы сверху, действия и справка — отдельной группой внизу, состояние сервера — карточкой в подвале панели | `Upload` дублировал кнопку в каждой карточке, `Links` дублировал заголовок, `About` и версия — не пункт меню |
| `Create ⌄` — шеврон без содержимого | Меню «Создать» раскрыто: пустая ссылка / файл / URL / галерея, с подписью у каждого пункта | Шеврон обещает выбор — выбор есть |
| Иконка фильтра без подписи рядом с `Total: 1` | Кнопка «Фильтры» с числом активных условий; активные условия показаны чипсами и снимаются по одному | Видно, что включено и сколько; состояние не теряется |
| «Upload» на карточке | «Заменить» (или «Загрузить файл», если файла нет) | «Upload» не отвечал на вопрос «это добавит второй файл или заменит текущий?» |
| Всё скрыто в «⋯», вход в версии и плейлисты не виден | В меню явные пункты «Плейлист и ротация», «Версии» со счётчиками; из меню открывается нужная вкладка панели | Самый частый сценарий после загрузки — посмотреть историю или включить ротацию |
| Пин виден на всех карточках постоянно | Пин появляется по наведению и остаётся видимым только у закреплённых | В покое карточка чистая, а не «три кнопки на каждой» |
| Иконка темы — солнце без состояния | Солнце/луна с `aria-pressed` и переключением по `T` | Понятно, что это действие, а не индикатор |
| Мобильного поведения нет | Сайдбар — выдвижная панель с затемнением и `Esc`, сетка — две карточки в ряд | На телефоне 244 px постоянной панели — треть экрана |
| Пустое место при одной ссылке | Пустое состояние объясняет, что произошло, и предлагает «Показать все» | Пустой экран — тоже экран |

Плюс сквозные улучшения из разбора (раздел 4 в `01-audit.md`): мета с иконками,
счётчик показов, бейдж доступа вместо выпадающего списка в карточке.

## Что улучшено относительно текущего интерфейса

Ссылки — на пункты из `01-audit.md`.

| # | Проблема сейчас | Как решено |
|---|---|---|
| P1 | Создание, поиск и сортировка в одной капсуле; на мобильном капсула не липкая | Тулбар разведён на два уровня: заголовок со счётчиками и главный CTA, ниже — отдельная строка поиска, фильтров и сортировки. В A/B строка липкая на десктопе, на мобильном уходит в поток |
| P2 | Меню «Загрузить» содержит «Добавить в плейлист» и «Версии» — не про загрузку | «Добавить/Заменить» = только способы (файл, URL, галерея). Плейлист, версии, статистика, доступ — отдельные пункты меню `⋯` и вкладки панели |
| P3 | Красная кнопка «Удалить» всегда рядом с основной | Постоянной кнопки удаления нет: она в `⋯`, внизу, за разделителем. В режиме выбора — отдельная кнопка с подтверждением |
| P4 | 5–7 контролов видны на каждой карточке одновременно | Три слоя: **покой** (превью, имя, мета, доступ) → **наведение** (Открыть, Заменить, копировать, пин) → **клик** (панель: доступ, версии, плейлист, статистика). На тач-устройствах hover-слой заменён постоянными иконками |
| P5 | Нет массовых операций и фильтров | Режим выбора + общий доступ, закрепить, экспорт, удалить. Фильтры-чипсы со счётчиками, которые пересчитываются при поиске |
| P6 | Кастомный `div`-селект + скрытый дубликат `<select>` | Нативные `<select>` и меню-кнопки: работает с клавиатуры без хаков |
| P7 | Насыщенный закатный акцент перетягивает внимание с обоев | Акцент — спокойный индиго `#4F5AD6` (5.6:1 с белым), используется точечно. Градиент бренда остался логотипу |
| P8 | Мелочи | Счётчик вынесен из поля поиска; подписи у полей; пин не «только на hover»; уровень доступа виден сразу; у ссылок без файла — явное состояние и кнопка загрузки |

Дополнительно: статус сервиса и версия на виду (B, D), прогресс ротации и
счётчики показов (C, A, D), единая панель деталей с вкладками вместо модалки на
четыре секции, осмысленные пустые состояния, `Ctrl/Cmd+F` — поиск,
`Ctrl/Cmd+G` — вид, `T` — тема, `Esc` — закрыть.

## Что я проверил

Браузера в песочнице нет (загрузка Chrome заблокирована), поэтому визуальную
проверку заменил технической:

1. **Структура** — HTML разобран парсером: незакрытых и лишних тегов нет, скобки
   в CSS сбалансированы, `proto.js` проходит `node --check`.
2. **Поведение** — все пять страниц выполнены в DOM-окружении, сценарии сыграны:
   фильтры, поиск, открытие/закрытие меню, режим выбора и счётчик, массовые
   действия, сортировка, переключение вида и темы, табы панели, выбор канала (C),
   выдвижной сайдбар и снятие активного условия (D). Ошибок JS нет.
   По ходу починил: табы, которые не переключали панели (A, D), и счётчик
   активных условий, который не обновлялся после удаления условия (D).
3. **Доступность** — нет дублей `id`, у всех картинок `alt`, у всех кнопок есть
   имя, все декоративные иконки `aria-hidden`, все поля подписаны.
4. **Контраст** — пары посчитаны скриптом, см. таблицу выше.

**Проверьте глазами** — отрендеренными макеты я не видел, поэтому что-то может
«съехать» на нестандартной ширине. Скажите, где не так — поправлю точечно.

## Финалист

`prototypes/final.html` + `final.css` — синтез A + C + D: сайдбар разделов и
состояние сервиса из D, карточки, три слоя действий, массовые операции и панель
деталей из A, прогресс смены кадра и сигнал «нет обращений» из C. Генерируется
скриптом из `a-library.html`, поэтому карточки и поведение в нём те же, что в A.

На десктопе (≥1024 px) шапка скрыта: логотип, тема, настройки и ссылка на стенд
живут в сайдбаре, а липкая строка фильтров прилипает к верху окна. На меньшей
ширине сайдбар превращается в выдвижную панель с бургером в шапке.

### Правки после выбора

`prototypes/final2.html` — та же версия после трёх замечаний: пульт ссылки стало
видно (кнопка «Пульт» в футере карточки, пункт «Открыть пульт» в ⋯ и клик по самой
карточке), интерфейс стал плотнее, а превью получили правила для любого медиа —
вертикалей, панорам, квадратов, PNG с прозрачностью, иконок и видео. Добавлен
переключатель из четырёх палитр (Индиго, Терракота, Шалфей, Графит) и страница их
сравнения `prototypes/palettes.html`. Первая версия финалиста оставлена для
сравнения «до/после». Разбор — в `04-final.md`.
