# Lanpaper 2.0 — редизайн админ-панели

Второй заход на оформление панели: вместо правки прежнего макета интерфейс
собран заново — от задач и от того, что реально умеет сервер. Макет лежит в
[`design/v2/`](v2/index.html): это кликабельный прототип, а не код приложения.

> **Статус:** дизайн готов и проверен в песочнице, в `admin.html` не переносился.
> Прошлая попытка (0.13.0) сломала раскладку, поэтому перенос — отдельный шаг по
> плану из раздела 12, с обязательным просмотром в настоящем браузере.
>
> Макет — не только картинка: он отвечает на то, чего у 0.12.1 не хватало
> (длинная библиотека, ошибка загрузки, добавление медиа по URL и из файлов
> сервера, массовый доступ, предел плейлиста). Список изменений поведения —
> в разделе 11-бис, он же — предмет обсуждения перед переносом.

## 0. Коротко

| Что было | Что стало |
| --- | --- |

| Медиа — только загрузкой файла | Плюс «По ссылке» (с проверкой URL) и «Из файлов сервера» — галерея с превью и весом |

## 1. Что не так с версией 0.12.1

Разбор по коду `admin.html` и `static/css/style.css` — это не «вкусовщина», а
конкретные места, которые стоят пользователю времени.

| № | Наблюдение | Чем мешает |
| --- | --- | --- |
| P1 | На плитке шесть постоянно видимых управляющих элементов: `.pin-btn`, ссылка-кадр, `.copy-url-btn` с подписью «Скопировать URL», `.access-row` с `<select>`, `.btn--upload` («Загрузить ▾»), `.btn--danger` («✕») | Плитка перегружена: вокруг кадра больше интерфейса, чем самого кадра. Разрушающее действие («✕») стоит рядом с основным и одинаково заметно |
| P2 | В `grid-view` плитка `minmax(262px, 1fr)`, но по высоте она ~300 px: 16:9-кадр (147 px) + инфо + селект доступа + ряд кнопок | На экран 1440×800 помещается меньше двух рядов ссылок. Библиотека читается медленнее, чем должна |
| P3 | `.toolbar-section` вверху — форма создания ссылки на первое место, поиск и сортировка во второе | Создать ссылку — редкое действие (одно на десяток просмотров), а занимает лучший участок экрана. На телефоне это три-четыре строки подряд перед первой карточкой |
| P4 | Фильтров нет: только поиск по имени и сортировка | В библиотеке на 40 ссылок нельзя ответить на вопросы «что у меня видео», «что не публично», «что закреплено», «где плейлисты» |
| P5 | `--gradient` (оранжевый → малиновый) + `--gradient-glow` на всех основных кнопках | Акцент конкурирует с фотографиями. В тёмной теме `#ff7250` со свечением выглядит громче всего на странице |
| P6 | Тёмная тема: фон `#0b0c10`, карточка `#121419`, текст `#f4f5f8` | Почти чёрный фон + белый текст = максимальная резкость; поверхности почти не разделены, карточки «слипаются» |
| P7 | `.access-row` — селект в каждой карточке | Восемь карточек = восемь одинаковых селектов, которые в 90 % случаев не трогают. При этом сам уровень доступа нигде не виден, пока не посмотришь в селект |
| P8 | Версии/плейлист/ротация/статистика живут в одном длинном `modal--wide`; вход — «Загрузить ▾ → Версии» | Главный экран управления ссылкой спрятан на два действия. На телефоне модалка — длинная прокрутка |
| P9 | Пустое состояние: SVG 104 px с `opacity: .35` и одна строка «Пока нет ссылок» | Не объясняет, что такое ссылка и с чего начать |
| P10 | На телефоне список — одна колонка: кадр во всю ширину + инфо + селект + ряд кнопок ≈ 340 px на ссылку | Одна ссылка на экран; сравнить две ссылки глазами нельзя |
| P11 | Идентификатор ссылки набран Unbounded 15 px, заголовок раздела — 700/1.25rem | Дисплейный шрифт в служебном тексте читается как «крик» и тянет внимание от кадра |
| P12 | Липкая «таблетка»-тулбар (`position: sticky; top: 12px`, размытие, тень) | Плавающая панель перекрывает карточки при прокрутке; на телефоне липкость отключена — поиск уезжает вверх и до него надо возвращаться |

## 2. Что задумано: «спокойная витрина»

Шесть принципов, из которых выведено всё остальное.

1. **Медиа — содержание, интерфейс — фон.** Ни одной кнопки поверх кадра; подписи
   на кадре ставим только там, где картинка не рассказывает сама (версия,
   плейлист, длительность). Всё, что не нужно постоянно, живёт в меню или в пульте.
2. **Одно главное действие на экран.** Ровно один акцентный элемент: «Новая
   ссылка» на десктопе, плавающая кнопка на телефоне. Остальное — «призрачные»
   кнопки с границей.
3. **Правило одного клика до пульта.** Клик по карточке открывает пульт ссылки;
   ничего не спрятано на два действия.
4. **Тишина цвета.** Один спокойный акцент, приглушённые нейтральные
   поверхности, границы вместо теней. Тень остаётся только у оверлеев.
5. **Плотность как уважение.** Информация на плитке сортируется по важности, а не
   по «чтобы было»: имя, тип, размер, размеры, дата, метки доступа и ротации.
6. **Одна разметка на все экраны.** Никаких «мобильных» и «десктопных» шаблонов:
   перестраивают только медиазапросы.

## 3. Каркас и адаптивность

```
┌──────────────────────────────────────────────────────────────┐
│  ▣ Lanpaper        12      [выбор][плитка│список][тема][⚙][+ Новая ссылка] │  ← липкая
│  🔍 Поиск по имени…   (Все 12)(Фото 9)(Видео 1)… [Доступ▾][Сортировка▾]     │
├──────────────────────────────────────────────────────────────┤
│  Ссылки 12                                                    │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐      │
│  │ кадр   │ │ кадр   │ │ кадр   │ │ кадр   │ │ кадр   │      │
│  │ имя  ⋯ │ │ имя  ⋯ │ │ имя  ⋯ │ │ имя  ⋯ │ │ имя  ⋯ │      │
│  │ мета   │ │ мета   │ │ мета   │ │ мета   │ │ мета   │      │
│  └────────┘ └────────┘ └────────┘ └────────┘ └────────┘      │
└──────────────────────────────────────────────────────────────┘
```

Никакого сайдбара: в приложении **один экран**, разделов («Фото», «Иконки»,
«Галерея») в нём нет, а место лучше отдать медиа. Прежние прототипы рисовали
сайдбар с разделами, которых не существует — из-за этого и появлялись
демо-данные, не совпадающие с `wallpapers.json`.

| Ступень | Ширина | Что меняется |
| --- | --- | --- |
| Широкий десктоп | ≥ 1280 px | Контент до 1440 px, поле 32 px, плитка от 252 px → 5 колонок |
| Десктоп | 1081–1279 px | Поле 28 px, плитка от 236 px → 4–5 колонок |
| Планшет / узкий ноутбук | 721–1080 px | Поле 20 px, плитка от 220 px, поиск 200–280 px рядом с чипами |
| Телефон | ≤ 720 px | Поле 14 px, плитка от 200 px; поиск сжимается до 168 px и делит строку с чипами (вместо трёх полос липкой шапки — две, ~96 px), «Новая ссылка» уезжает в плавающую кнопку, пульт открывается снизу |
| Телефон | ≤ 560 px | Плитка от 136 px → две колонки как в галерее, короткий плейсхолдер «Поиск», в шапке только иконки |
| Очень узкий | ≤ 340 px | Одна колонка |

Ключевые решения по адаптиву:

- **Липкая шапка одна, а не три плавающих элемента.** Верхняя строка (кто я, что
  могу) и строка поиска с фильтрами липнут вместе как один блок — в отличие от
  0.12.x, где поиск на телефоне уезжает вверх.
- **Плитка вместо списка на телефоне.** Две колонки по ~170 px показывают 6–8
  ссылок на экран вместо одной.
- **Список — для широких экранов и точного поиска**: кадр 124 px слева, текст
  справа, высота строки ~60 px.
- **Пульт**: справа (460 px) на десктопе, снизу во весь экран (`max-height: 94dvh`,
  ручка-грабер) на телефоне. Одно и то же содержимое, разные оболочки.

## 4. Плитка: что видно и как вписывается кадр

Кадр всегда 16:9 — так сетка не «плывёт» на необычных пропорциях. Меняется
способ вписывания:

| Медиа | Как показывается | Подписи |
| --- | --- | --- |
| Фото 16:9 и шире | `cover`, кадр заполнен | формат, размеры, размер, дата |
| Панорама ≥ 2:1 | `cover` (полоса читается) | то же + размеры |
| Вертикаль и квадрат (< 1.25:1) | `contain` на матовой подложке `--matte` | то же |
| PNG (иконки, логотипы) | `contain` + шахматка из `--checker-a/b` | то же |
| Видео | кадр + круглая кнопка воспроизведения по центру, справа снизу длина `0:18` | + длительность |
| GIF | кадр + метка «анимация» | + метка |
| Плейлист | кадр + метка «6 в плейлисте» | + метка ротации в тегах |
| Файла нет | пунктирная рамка и иконка «нет файла» | «Нет файла» вместо размера |

Подписи на кадре — тёмные «таблетки» без размытия подложки: подписей бывает до
четырёх на карточку, а каждая размывка — отдельный слой композитора.

Метаданные под именем: `JPEG · 1376×768 · 75 КБ · 28 сент.` Разделители
нарисованы через CSS (`span + span::before`), поэтому скрытая на узком экране
часть не оставляет висящую точку.

Теги под метаданными показываются **только когда они что-то значат**: уровень
доступа, если он не публичный (`🔒 Локальная сеть`, `🔑 По секретной ссылке`,
`👤 Только админ`), и метка ротации. У публичной ссылки без ротации тегов нет —
плитка остаётся чистой.

Закрепление — тонкая акцентная полоса слева по краю карточки, а не кнопка с
иконкой: состояние видно, места не занимает.

## 5. Пульт ссылки

Одна панель на все задачи ссылки. Открывается кликом по карточке, из меню «⋯»
(«Открыть пульт») и из тоста после создания ссылки.

```
ПУЛЬТ ССЫЛКИ
tv                                        [✕]
12 480 запросов · 1,2 ГБ · 4 мин назад
[Медиа] [Версии] [Плейлист] [Доступ]
──────────────────────────────────────────
lanpaper.local/ tv              [копировать]
[ превью 16:9 ]
Тип      JPEG · 1376×768
Размер   75 КБ
Изменён  вчера
Версия   v3 · 2 в архиве
ЗАМЕНИТЬ МЕДИА
[ Файл с устройства ] [ По ссылке ]
[ Из галереи сервера ] [ В плейлист ]
──────────────────────────────────────────
[Удалить]                        [Готово]
```

| Вкладка | Что внутри | Почему отдельно |
| --- | --- | --- |
| **Медиа** | URL с копированием, превью, сведения о файле, четыре способа заменить содержимое | это то, что делают в 80 % случаев |
| **Версии** | полоса занятого бюджета, текущая версия, архивные: открыть / восстановить / удалить | замена файла не должна быть страшной — рядом видно, что старое на месте |
| **Плейлист** | список файлов за одной ссылкой, ротация (вкл/выкл, интервал, порядок) с кнопкой «Сохранить», которая включается только при изменениях | редкая, но сложная настройка; в 0.12.x она требовала разбираться в модалке со всем сразу |
| **Доступ** | четыре уровня радио-карточками с пояснением, ниже — секрет и его смена для уровня «по секретной ссылке» | уровень доступа перестал быть селектом в каждой плитке и получил объяснение |

Плюс общее для всех вкладок: статистика строкой в шапке, «Готово» и «Удалить» в
закреплённом подвале. Переключение уровня доступа обновляет панель **без потери
прокрутки и фокуса** (в прототипе это отдельно проверено тестом).

## 6. Создание ссылки, пустота, скелетоны, выбор пачкой

- **Создание.** Диалог: превью адреса `lanpaper.local/…`, проверка на месте
  (пусто / недопустимые символы / занято), `Enter` отправляет. После создания
  карточка подсвечивается и уезжает в видимую часть, а тост предлагает сразу
  загрузить файл. Пустая ссылка — нормальное состояние: файл можно положить позже.
- **Пустое состояние.** Объясняет, что такое ссылка, и даёт два пути: «Создать
  ссылку» и «Перетащить файлы» + подсказка, что перетаскивание работает в любом
  месте окна.
- **Ничего не найдено** — отдельное состояние, чтобы пустой результат поиска не
  выглядел как пустая библиотека. Есть кнопка сброса фильтров.
- **Скелетоны** показывают будущую сетку (кадр + две строки), а не спиннер.
- **Режим выбора** (клавиша `s` или кнопка в шапке): у каждой карточки появляется
  кружок, снизу — панель «Выбрано: 3 · Закрепить · Скопировать URL · Удалить».
  Требует серверных массовых операций или цикла по ссылкам — помечено как P2.

## 7. Дизайн-система

Токены — в [`v2/tokens.css`](v2/tokens.css), компоненты — в `v2/ui.css`, каркас —
в `v2/layout.css`. Значения:

| Группа | Значения |
| --- | --- |
| Отступы | 4 · 8 · 12 · 16 · 20 · 24 · 32 · 44 · 64 px |
| Радиусы | 6 · 9 · 12 · 16 (карточка) · 22 (панель) · 999 (чипы, кнопки) |
| Высоты | 30 (мелкие) · 36 (обычные) · 44 (крупные и все поля на тач-экранах) |
| Тени | `--shadow-xs/sm/md/lg`; на карточках теней нет — только границы |
| Тени фокуса | `0 0 0 3px rgba(accent, .16)` + `outline: 2px` для клавиатуры |
| Типографика | 11 · 12 · 13 · 14 (база) · 16 · 20 · 24 · 30 px; Manrope 400–800 |
| Дисплейный шрифт | Unbounded 500 — только логотип и крупные числа |
| Движение | 120 / 180 / 260 мс, `cubic-bezier(0.22, 0.61, 0.36, 1)`; всё отключается через `prefers-reduced-motion` |

Что убрано по сравнению с 0.12.x: градиентные кнопки и их свечение
(`--gradient`, `--gradient-glow`), тени на карточках и липкой панели, размытие на
подписях кадра и hover-кнопках. Иерархия строится границами и цветом текста —
это дешевле и спокойнее выглядит.

## 8. Палитры и тёмная тема

Пять палитр меняют **только** подложку и группу акцента; текст, границы и статусы
общие, поэтому контраст не зависит от выбора пользователя. Тёмная тема не
инвертирует светлую, а задаётся отдельно: фон `#14161B`, поверхность `#1B1E24`,
поверхность-2 `#22262E` — поверхности различимы, но не «светятся».

| Палитра | Акцент (светлая / тёмная) | Белый текст на акценте | Акцент на карточке |
| --- | --- | --- | --- |
| **Индиго** (по умолчанию) | `#5A66B5` / `#9AA4E8` | 5.25:1 | 5.25:1 |

## 9. Доступность

- **Фокус.** Видимый `:focus-visible` (2 px акцента + отступ), у всех полей —
  рамка с мягким кольцом. Контур повторяет радиус элемента, поэтому круглые
  кнопки не превращаются в квадраты.
- **Клавиатура.** `/` — поиск, `n` — новая ссылка, `t` — тема, `g` — вид,
  `s` — режим выбора, `Esc` — закрыть меню/панель, `Tab` замкнут внутри
  панели и диалогов. Список горячих клавиш — в настройках.
- **Семантика.** Одна панель с `role="tabpanel"`, подпись которой следует за
  активной вкладкой; `role="status"` у тостов; `aria-pressed` у переключателей
  вида и чипов; `aria-modal` + focus-trap у оверлеев; скрытый текст у иконочных
  кнопок; чекбокс выбора получает доступное имя с именем ссылки.
- **Крупные зоны нажатия.** На тач-экранах (`@media (hover: none)`) все поля и
  иконочные кнопки растягиваются до 44 px, не меняя вид на десктопе.
- **Движение.** Все анимации выключаются при `prefers-reduced-motion: reduce`.
- **Разметка.** `html-validate` (recommended) по `v2/index.html` и `v2/screens.html`
  не находит структурных ошибок; остаются только замечания к шаблонам
  (`role="radio"` на кнопках, пустые `h2`/кнопки, которые заполняет скрипт).

## 10. Почему стало легче

| Что | 0.12.x | 2.0 |
| --- | --- | --- |
| DOM на одну ссылку | ~10 управляющих элементов | 2 (карточка, «⋯») + 7 пунктов в меню по требованию |
| Высота плитки при 262 px | ~300 px | ~188 px |
| Размытие подложки | тулбар + минимум по кнопке в каждой карточке | только шапка, затемнение и панель массовых действий |
| Градиенты и свечения | на всех основных кнопках | нет |
| Липких слоёв | липкая «таблетка» тулбара (с тенью) | один липкий блок шапки |
| Изображения | `loading="lazy"` | то же + `decoding="async"` + `aspect-ratio` (нет скачков раскладки) |
| Шрифты | Manrope (39 КБ) + Unbounded (9 КБ) | без изменений: Unbounded только для логотипа и чисел |

Если на слабом устройстве размытие шапки всё же мешает — достаточно заменить
`--glass` на `var(--bg)` в `tokens.css`: каркас от этого не поедет, потому что
размеры и отступы от размытия не зависят.

## 11. Что осознанно не вошло

- **Сайдбар с разделами.** В приложении нет разделов; прежние прототипы рисовали
  их на демо-данных. Когда появится настоящее разделение (например, «мусор» или
  «теги»), место под него — в шапке рядом с поиском.
- **Массовые операции на сервере.** Прототип умеет выбирать несколько ссылок, но
  в API нет пакетных ручек; пока это цикл по `PATCH`/`DELETE`, поэтому кнопка
  помечена как P2.
- **Отмена удаления по-настоящему.** Тост «Вернуть» в макете возвращает ссылку в
  память; в приложении для этого нужно мягкое удаление (файлы остаются на диске
  до подтверждения). Отдельная задача, но именно она снимает страх удаления.
- **Выдвижная панель деталей без затемнения** (чтобы видеть библиотеку). Требует
  отдельной работы по фокусу и Escape — сейчас затемнение честнее.
- **Темы «как в системе» с автоматическим переключением по расписанию.**

### 9-бис. Нативные элементы выбора

Группа «Тема» собрана на настоящих `<input type="radio">`, а не на кнопках с
`role="radio"`: состояние видно в разметке, стрелки и пробел работают без
скриптов, скрипту остаётся только слушать `change`. То же — у образцов акцента
(радио лежит поверх цветного круга и рисует кольцо выбора). Роль
`role="radiogroup"` осталась на контейнере, имя — через `aria-labelledby` на
заголовке раздела. Кнопочные варианты `.segment__item` (вкладки пульта,
«Плитка / список») сохранены: там уместны `role="tab"` и `aria-pressed`.
`:has()` использован только в `.choice`; порог браузеров для него —
Chrome 105 / Safari 15.4 / Firefox 121 (2022–2023 годы).

## 11-бис. Что изменилось в поведении

Просьба была не только про вид: «все текущие функции, безопасность и
производительность должны остаться на том же уровне или лучше». Поэтому список
ниже — не украшения макета, а конкретные изменения поведения, которые перейдут
в приложение вместе с разметкой. Ни одна ручка API при этом не меняется.

| # | Было в 0.12.1 | Стало в макете | Зачем |
| --- | --- | --- | --- |
| 1 | Список ссылок отрисовывался весь: 40 карточек — 40 превью сразу | Порции по 12, «Показать ещё» с остатком, «видно 12 из 20», счётчик в шапке. Любая смена поиска, фильтра, доступа или сортировки сбрасывает порцию | Меньше работы на кадр при большой библиотеке, счётчик отвечает на «сколько у меня всего» |
| 2 | Пустой экран при недоступном сервере — тот же, что при пустой библиотеке | Отдельное состояние ошибки с текстом и «Повторить»; пустое состояние говорит «ссылок нет / ничего не нашлось» | Пустая библиотека и упавший запрос — разные ситуации с разными действиями |
| 3 | Медиа добавлялось загрузкой файла (плюс перетаскивание) | Тот же диалог предлагает «С телефона», «По ссылке» и «Из файлов сервера»; адрес проверяется (`https?://`, 2048 символов, известные расширения) до отправки | Данные уже есть на сервере или в сети — незачем скачивать и заливать заново |
| 4 | Замена медиа не спрашивала, что делать с историей | Любая замена архивирует прежний файл в версии и обрезает историю по лимиту из конфигурации; номер текущей версии растёт | История версий остаётся предсказуемой и не растёт бесконечно |
| 5 | Плейлист позволял добавить сверх предела — ошибка приходила от сервера | Кнопка добавления исчезает на пределе, вместо неё подсказка «Плейлист заполнен: до 8 файлов»; число берётся из конфигурации | Предел видно до нажатия, а не после |
| 6 | Уровень доступа менялся по одной ссылке | Панель выбора умеет сменить доступ сразу выбранным, одним запросом на ссылку, с одним итоговым тостом | Массовая правка — частая операция при открытии/закрытии доступа |
| 7 | Занятое место под версии нигде не считалось | Вкладка «Версии» показывает занятое и бюджет, кнопка удаления гаснет, когда история пуста | Бюджет — настройка сервера, о нём нужно знать заранее |
| 8 | Проверка ID при создании — только по нажатию кнопки | ID проверяется через 250 мс после ввода: «свободен» или «занят», кнопка создания гаснет до ответа | Ошибку видно до отправки, а не после |
| 9 | Фильтры, доступ и сортировка не имели счётчиков | У каждого чипа — число ссылок; поиск ищет по имени и типу, а по переключателю — ещё и по доступу, размеру, версии, размерам кадра | Понятно, сколько ссылок попадёт под фильтр, до нажатия |
| 10 | Горячие клавиши: `/`, `n`, `Esc` (плюс `Ctrl/⌘ + N/F/G/T`, о которых знали не все) | Те же сочетания остались, добавлены однобуквенные `t` (тема), `g` (вид), `s` (выбор); в настройках виден весь список | Никто не теряет привычку, но короткие клавиши находятся |
| 11 | Созданная ссылка в длинной библиотеке оказывалась за пределами списка | Новая ссылка попадает в видимую порцию, подсвечивается и «подводится» прокруткой; то же после переименования и загрузки файлов | Тост «создана» без ссылки на экране — худший вид успеха |
| 12 | Поворот изображения и интервалы не отражались в интерфейсе состояниями | Кнопки отражают сохранённое состояние и блокируются, пока нечего сохранять | Меньше пустых нажатий и ложных «сохранено» |

**Чего изменения не касаются.** Ручки (`/api/wallpapers`, `/api/link`,
`/api/upload`, `/api/external-images`, `/api/compression-config`), формат
`wallpapers.json`, имена полей, уровни доступа, токены и уже выданные адреса —
всё как было. Экспорт/импорт сохраняет тот же формат (`version: 1.0.0`), токены
по-прежнему не выгружаются. Порционный рендер — это клиентская отрисовка: сервер
и сейчас умеет отдавать страницы (`page_size`), но макет ей не пользуется, чтобы
не менять порядок и не терять уже загруженное.

## 12. Перенос в приложение

Порядок работ — от проверяемого к рискованному. Ни один шаг не меняет API,
формат `wallpapers.json` и существующие ссылки: это только оформление, разметка и
клиентская логика.

1. **Токены.** Значения из `v2/tokens.css` переносятся в блок `:root` и
   `body.dark` в `static/css/style.css` (тёмная тема у приложения на классе
   `body.dark`, у макета — на `html[data-theme]`; свести к одному).
2. **Компоненты.** `v2/ui.css` → `style.css` (кнопки, чипы, поля, карточка,
   панель, тосты, пустое состояние, скелетоны). Имена классов в макете новые,
   поэтому переносить их нужно вместе с разметкой, а не «навешивать» на старые.
3. **Разметка.** `v2/index.html` → `admin.html`: шапка с двумя строками, строка
   фильтров, сетка без ряда кнопок, шаблоны `tplCard`, `tplPanel`, `tplCreate`,
   `tplSettings`, `tplConfirm`.
4. **Логика.** `v2/app.js` → `static/js/app.js`: рендер карточки, фильтры и
   сортировка (данные уже приходят в `/api/wallpapers` — `category`, `pinned`,
   `accessLevel`, `history`, `items`, `rotate`, `stats`), пульт, диалоги, тосты.
5. **Переводы.** Ключи макета и их соответствие приложению:

| Ключ макета | Ключ в `static/i18n/*.json` |
| --- | --- |
| `links` | `existing_links` |
| `delete` | `delete_btn` |
| `cancel` | `modal_cancel` |
| `close` | `modal_close` |
| `uploaded` | `upload_success` |
| `link_created` | `created_success` |
| `renamed` | `renamed_success` |
| `restored` | `restored_success` |
| `pinned_toast` / `unpinned_toast` | `pinned` / `unpinned` |
| `rotate_sequential` / `rotate_random` | `rotate_order_sequential` / `rotate_order_random` |
| `open_media` | `aria_open_image` |
| `version_deleted`, `item_removed`, `append_success`, `rotate_saved`, `token_rotated`, `access_updated`, `invalid_id`, `link_taken`, `copy_url`, `copy_error`, `versions_history`, `playlist_empty`, `playlist_remove`, `rotate_enabled`, `rotate_interval`, `stats_title`, `stats_none`, `install_app`, `regen_previews`, `settings_language`, `export_json`, `import_json` | совпадают по имени — подставляются как есть |

Остальные ключи макета — новые (фильтры, пульт, палитры, массовые действия,
пустые состояния): 195 ключей в каждом языке, из них 58 уже есть в приложении
под тем же именем, остальные — новые. В макете переведены русский и английский;
ещё четыре языка (`de`, `fr`, `it`, `es`) берутся из `static/i18n/*.json` при
переносе — ключи для них уже названы так же, как в приложении. Тест `tests/i18n.test.cjs` следит за полнотой наборов — его
список ключей придётся обновить вместе с переносом.

6. **Сервис-воркер.** `static/sw.js`: поднять номер кеша (`lanpaper-static-v7`),
   иначе у установленной PWA останется старый CSS.
7. **Версия.** Публиковать как **0.14.0**: номер 0.13.0 занят откаченной сборкой,
   и путать их не стоит.
