# Аудит Lanpaper: безопасность, оптимизация, восстановление функционала

Дата: 2026-09-27 · Ветка: `arena/01a0e3b9-lanpaper` · База: `main` (после PR #17 и PR #18)

Проведён полный аудит кодовой базы (Go-бэкенд, фронтенд, service worker, конфигурация) поверх уже смерженных PR #17 и PR #18. Все изменения проверены юнит-тестами (`go test -race ./...`), `go vet`, `gofmt`, `node --test tests/*.test.cjs` и сквозными тестами в реальном браузере (Chromium), включая отдельный прогон в среде «легаси-браузера» со специально удалёнными современными API.

---

## 🐛 Восстановление функционала (главное: «не могу создать ссылку»)

### 1. Хрупкая цепочка инициализации UI убивала весь админ-интерфейс
**Симптом:** панель могла полностью «умереть»: карточки не рисовались, кнопка Create не работала (форма делала нативный submit и перезагружала страницу). Достаточно было отсутствия одной нестандартной API в конкретном браузере (Smart-TV WebView, старый Safari ≤13, «обрезанные» Electron/WebView, обычный **HTTP** в LAN).

**Причина (сохранилась и после PR #18):** весь UI собирался в одной async-цепочке `DOMContentLoaded`, где исключение в *любом* шаге обрывало всё остальное:
- `window.matchMedia(...).addEventListener` — отсутствует в Safari ≤13 → падение в `initTheme()` → до `setupGlobalListeners()` дело вообще не доходило;
- `CSS.escape` — отсутствует в старых движках → падение при отрисовке карточек;
- `navigator.clipboard` — **отсутствует на обычном HTTP** (типичный LAN-доступ к Lanpaper по http://192.168.x.x:8080) → падение кнопки «Copy URL»;
- `new AbortController()` в `setupCardEvents` — **воспроизведено**: при отсутствии API выбрасывал исключение прямо при рендере карточек, `renderLinks` полностью падал и список оставался пустым («Failed to load links»), хотя сервер отдавал данные;
- `Element.animate` — падение в обработчике создания.

**Исправлено (`static/js/app.js`):**
- каждый шаг инициализации изолирован (`safeStep`/`safeStepAsync`) — один сбой не роняет остальное;
- обработчики форм/модалок биндятся **первым шагом** — создание ссылки работает даже при полном отказе загрузки данных/переводов;
- совместимые фолбэки: `CSS.escape`, `matchMedia` (`addListener`), `copyToClipboard()` с `execCommand('copy')` для HTTP-LAN, опциональный `AbortController` (ручное снятие слушателей в cleanup), `Element.animate`;
- при ошибке загрузки списка показывается понятное сообщение прямо в пустом состоянии (в стиле приложения) + ключи i18n `load_error_hint`, `auth_required`, `forbidden` во всех 6 языках.

### 2. Загрузка MP4 с брендом `isom`/`iso2`/`avc1`/`M4V ` отклонялась
**Причина:** `http.DetectContentType` реализует WHATWG-сниффер, который распознаёт MP4 только при наличии бренда `mp4*` в ftyp-box. Видео с камер/телефонов часто несут только `isom/iso2/avc1` → «Unsupported file type». Хуже того: файлы, скачанные по URL, лежат во временном файле **без расширения** — fallback на расширение не спасал.

**Исправлено (`handlers/upload.go::inspectMediaFile`):** любой ISO-BMFF/MP4 с валидным ftyp-box принимается независимо от бренда. Тест `TestInspectMediaFileAcceptsAllMP4Brands` (isom/mp42/M4V + отказ для мусора).

### 3. Мелочи работоспособности
- `export-import.js` больше не зависит от объекта `DOM` из `app.js` (при сбое app.js падал целиком);
- `apiCall`: явные `credentials: 'same-origin'` (WebKit-исторически опускал HTTP-auth в fetch) и внятные сообщения для 401/403;
- `loadLinks` терпит обёрнутый/постраничный ответ `/api/wallpapers` (защита от «пустого списка» при изменении API).

## 🔒 Безопасность

### Что сделано в этом PR (поверх PR #17/#18)
1. **Логирование CSRF-отклонений** (`middleware/security.go`): каждое отклонение кросс-сайт-записи логируется с диагностикой (метод, путь, Origin, Sec-Fetch-Site, Host, IP) и подсказкой про `TRUSTED_PROXY` — иначе волна 403 при кривом reverse-proxy выглядит как «сервер сломан» без единой улики в логах.
2. **Полная изоляция рендера от отсутствующих API** (см. выше) — это также и вопрос безопасности: «тихий» отказ панели администратор не отличим от взлома.

### Что было сделано ранее и подтверждено аудитом (PR #17/#18) — проверено, работает
- **Fail-closed аутентификация:** без кредов / при полу-конфигурации админ-эндпоинты отвечают **503** (не «открыто для всех»); предупреждения при старте; `DISABLE_AUTH=true` — только для прокси-режима; constant-time сравнение, анти-брутфорс.
- **SSRF:** пиннинг валидированных публичных IP на каждом редиректе и через HTTP/HTTPS/SOCKS5-прокси (включая absolute-URI в запросе к прокси — защита от DNS rebinding), стриминг на диск с лимитом. Проверено: `127.0.0.1`, `localhost`, `[::1]`, `169.254.169.254`, `file://` → 400.
- **Path traversal:** `ValidateAndResolvePath` + symlink-резолв, запрет абсолютных/Windows-путей. Проверено: `../../etc/passwd`, `../data/wallpapers.json` → 400.
- **Media isolation:** allowlist статики (`os.OpenRoot`, без симлинков), `/static/images/*` → 404, листинги → 404, приватные медиа/превью под Basic Auth, `sandbox`-CSP для SVG, `Referrer-Policy: no-referrer`, CORP.
- **Декодирование:** бюджет `MaxImagePixels` (decompression bomb), общий счётчик пикселей, лимит одновременных загрузок, потоковый чисто-Go WebP-декодер.
- **Целостность хранилища:** атомарные коммиты `wallpapers.json`, локи на запись, копии из `Get`/`GetAll` (нет data race с раздачей), транзакционный rename с откатом файлов, миграция легаси-каталога без следования симлинкам, отказ загружать битые метаданные.
- **CSRF:** `Sec-Fetch-Site`/`Origin`-проверки (включая X-Forwarded-Host только от `TRUSTED_PROXY`), HSTS только при реальном TLS (не по подделанному заголовку).
- **XSS/инъекции:** тосты через `textContent`, имена ссылок ограничены `[A-Za-z0-9_-]`, `Content-Disposition` без инъекций, `SUPPORTED_LANGS` allowlist для i18n-путей.
- Уровни доступа (public/local/token/auth): полный матричный тест (403/403/200 c `?token=` и `X-Access-Token`; local=200 с loopback; auth=401/200).

## 📋 Что можно сделать далее (не блокирует, осознанно вне объёма)
1. **Полноценный backup/restore медиа** (браузерный экспорт/импорт переносит только метаданные) + `fsync` перед rename для защиты от внезапного обесточивания.
2. **Хранение кредов хешем** (bcrypt/argon2) вместо plaintext в env/config.json; сессионные cookie вместо Basic Auth.
3. **CSRF-токены (double-submit)** как вторая линия поверх Sec-Fetch-Site для совсем старых браузеров.
4. **Хранилище за интерфейсом** (файл/Bolt/SQLite) для библиотек с тысячами ссылок; межпроцессные локи, если когда-нибудь поднимут несколько инстансов на одной `data/` (сейчас — single instance).
5. **Хот-перезапуск и graceful shutdown** с отложенной выгрузкой очереди загрузок.
6. **Animated WebP** — декодер читает первый кадр; можно добавить явную обработку/конвертацию.
7. **Квоты диска** на каталог медиа (сейчас есть `MAX_IMAGES`/prune старых изображений).
8. **Метрики** (Prometheus `/metrics` под админ-auth): глубина очереди загрузок, лимиты, ошибки декодирования.
9. **E2E в CI** (puppeteer/playwright) — локально прогон сделан вручную; вынести в GitHub Actions следующим шагом.
10. **Multi-arch Docker smoke** для arm64 (сборка идёт в CI, runtime-проверка только amd64).
