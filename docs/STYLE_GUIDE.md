# Как править оформление Lanpaper

Источник правды — **`static/css/style.css`**. Он подключается напрямую:
сборка, Sass, Tailwind и генерация CSS не нужны. `design/v2/` — исторический
макет; изменение его стилей не меняет приложение.

## Где что менять

В начале `style.css` есть карта разделов. Ищите заголовки и имена селекторов,
а не номера строк: форматирование может их сдвинуть.

| Что хочется изменить | Где править |
| --- | --- |
| Фон и поверхности | `:root`: `--bg`, `--surface`, `--surface-2`, `--surface-hover` |
| Текст и акцент | `--text*`, `--accent*`; проверять контраст в обеих темах |
| Тёмную тему | `html[data-theme="dark"]` |
| Конкретную палитру | `html[data-palette="…"]` и её комбинированное правило с `data-theme` |
| Скругления | `--r-*`; `--r-full` оставляет кнопки/чипы круглыми |
| Шрифт и размер текста | `--font-*`, `--t-*`, `--fw-*`, `--leading*` |
| Общие отступы | `--s-*`: 4, 6, 8, 10, 12, 16, 20, 24, 32, 44, 64 px |
| Плитку | `--card-padding`, `--card-gap`, `--card-padding-phone` |
| Строку списка действий | `--row-padding` (это `.row`, **не** `.grid--list`) |
| Содержимое боковой панели | `--sheet-body-padding` |
| Пункт меню | `--menu-item-padding` |
| Строку версии/плейлиста | `--version-row-padding` |
| Пункт выбора файла | `--picker-item-padding` |
| Ширину страницы и поля | `--maxw`, `--gutter` + адаптивные переопределения |
| Тени и фокус | `--shadow-*`; не удалять видимый фокус клавиатуры |
| Скорость переходов | `--dur-*`, `--ease*`; специальные движения темы/шестерёнки описаны отдельно |
| Порядок глобальных слоёв | `--z-*`; локальные `z-index: 1/2` внутри компонентов — отдельный контекст |

`--s-1-5` означает промежуточный шаг **6px**, `--s-2-5` — **10px**.
Цифры в имени — шаг шкалы, не количество пикселей. Существующие имена
`--s-1`…`--s-9` сохранены. Нечётные 1/3/5/7/9/11px часто являются оптическими
поправками; размеры значков, рамок и геометрия контролов не превращены
механически в отступы.

### Пример: чуть свободнее плитка

В существующем `:root` измените значения, не добавляя второе объявление:

```css
--card-padding: var(--s-3) var(--s-4);
--card-padding-phone: var(--s-2-5) var(--s-3);
```

Телефонный токен применяется к плиткам при ширине ≤560px. Строки
`.grid--list .card__body` имеют собственные отступы, чтобы не раздувать список.
Их адаптивные правила намеренно сохранены. Токены-композиции лучше менять
в `:root`: ссылки на другие переменные вычисляются в контексте их объявления.

## Правила, которые сохраняют предсказуемость

- Порядок: базовые токены → тёмная тема → палитры → компоненты → каркас и
  адаптивные правила. Комбинированный селектор палитры и темы специфичнее
  одиночного. Настраивая цвет, проверяйте все нужные переопределения.
- Не сортируйте правила и свойства автоматически. Поздний shorthand может
  сбросить ранний longhand, а повторное свойство с другим значением может быть
  fallback (`100vh` перед `100dvh`). Одинаковые media queries тоже нельзя
  объединять без проверки порядка относительно соседних правил.
- Не поднимайте специфичность через новые ID и `!important` ради исправления
  одного состояния. Сначала найдите существующий компонент и его модификатор.
- Сохраняйте `[hidden]`, `.is-hidden`, `:focus-visible`, reduced-motion,
  прокрутку фильтров/вкладок, safe-area и touch-target правила.
- Не меняйте `display`, `position`, `overflow`, порядок слоёв и брейкпоинты
  как обычные декоративные параметры: это уже изменение поведения раскладки.
- Стили должны оставаться в CSS. CSP не разрешает добавлять `<style>` и
  атрибуты `style="…"` в HTML; существующая динамическая CSSOM-логика — отдельно.
- Вордмарк входа сохраняет пропорции 4:1 и `height: auto`. Его размер и
  доступное имя проверяются Go-тестом.

## Форматирование и проверки

Node.js нужен **только разработчику**, не серверу и не браузеру:

```sh
npm ci --prefix tools --ignore-scripts   # первый запуск / после обновления lockfile
npm run format --prefix tools           # форматирует только style.css
npm run check --prefix tools            # формат + структура + токены + тесты проверки
node tools/check-contrast.mjs            # контраст боевых цветов
node --test tests/*.test.cjs             # контракты и логика фронтенда
```

Форматировщик не сортирует правила. Контракты анимаций проверяют значения
свойств, а не пробелы и переносы строк. Их менять можно; менять значения
анимаций — осознанно, вместе с ожиданиями тестов.

Структурная проверка ловит повреждённые блоки, повторные объявления и ссылки
на необъявленные переменные. Все используемые CSS-токены должны быть объявлены
в файле, даже если у `var()` есть fallback. Проверка не доказывает доступность
переменной в каждом контексте наследования и не валидирует все возможные
значения CSS-свойств. Контраст проверяет заданные пары непрозрачных цветов,
а не каждый отрисованный пиксель. Браузерные тесты остаются необходимыми.

Проверьте вручную светлую/тёмную тему, палитры, плитку/список, телефон,
вход, открытое меню/панель, офлайн-баннер и клавиатурный фокус. Для раскладки
проверьте ширины по обе стороны изменяемого брейкпоинта, а также длинные
переводы и увеличенный масштаб.

## Чтобы обновление действительно появилось

1. Поднимите `STATIC_CACHE` в `static/sw.js` и обновите его проверку в
   `tests/frontend-contract.test.cjs`.
2. Перезапустите сервер: хеши версий статических файлов вычисляются при старте.
3. Не меняйте `design/v2` в надежде обновить панель и не добавляйте новые CSS-файлы
   без серверного allowlist и проверки CSP.

Читаемость важнее экономии переносов строк. CSS остаётся одним кешируемым
ресурсом: форматирование не добавляет запросов, JS-работы или runtime-зависимостей.


## Studio (0.19.0)

- `static/css/style.css` остаётся базой компонентов, размеров медиа и страницы
  входа. `static/css/studio.css` подключён **только в admin.html** и содержит
  монохромную основу, композицию каталога и финальные правила Studio. Редактируйте
  соответствующую секцию, не добавляйте правила стенда `/demo/` в production.
- `static/js/studio-layout.js` переставляет существующие DOM-кнопки, не копирует
  их и сохраняет обработчики/фокус. Порог навигации — 760px, нижнего пульта —
  720px. Выбор сворачивания хранится отдельно от данных библиотеки.
- `--card-padding` и `--card-padding-phone` остаются рабочими токенами плиток;
  список имеет собственные размеры. `design/mono/media-contract.test.mjs`
  теперь проверяет именно **боевой** Studio CSS, включая штатные breakpoints.
- `.palette-controls` выравнивает образцы и название по центру. `applyPalette(node)`
  заполняет название в клоне настроек до вставки в DOM.
- `.video-preview` и плеер позиционируются внутри рамки: процентной высоты в
  неограниченной grid-ячейке недостаточно для портретного видео. Не загружайте
  видео в сетке и не возвращайте автоматический `src`: он устанавливается только
  при нажатии. `stopMedia` освобождает загрузку при закрытии и смене вкладки.
- `.sheet__grip` — нативная кнопка с hit-area 88×44px. Жест ограничен ручкой;
  обработчиков touchmove на документе и блокировки скролла содержимого нет.
  Размеры coarse-pointer кнопок — минимум 44px. Прокрутка, фокус и подтверждения
  остаются под управлением `overlay-controller.js`.
- Новые CSS/JS/шрифты перечислены в `static.go` и `static/sw.js` (v15). Лицензия
  Manrope: `static/fonts/OFL-Manrope.txt`. Новые assets не требуют CDN или
  ослабления CSP. API и медиа не попадают в кеш service worker.

Проверки: `npm run check --prefix tools` включает оба CSS, контраст Studio и
контракт геометрии; `node tools/check-contrast.mjs` отдельно проверяет базовую
палитру страницы входа. `tests/e2e/studio.spec.js` проверяет реальную панель,
включая воспроизведение, доступ к Range, touch и первую отрисовку палитры.
