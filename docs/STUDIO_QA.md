# Studio 0.19.0 — проверка перед мержем

Дата: 2026-10-13. Продолжение PR #36; перенос Studio в основное приложение и
on-demand видео согласованы отдельно от первоначальной косметической правки.

## Реализация

- Production: `admin.html`, `static/css/studio.css`, `static/js/studio-layout.js`.
  Используются существующие элементы, обработчики и API, не HTML/API стенда.
  Manrope поставляется локально с OFL. Страница входа не подключает Studio CSS.
- Название палитры заполняется в ещё не смонтированном клоне настроек;
  `.palette-controls` выравнивает его с образцами. Смена языка обновляет название.
- Видеофайлы не запрашиваются сеткой и при простом открытии пульта. Только
  нажатие создаёт `<video controls playsinline>` с `/api/preview/{name}`.
  Смена вкладки/закрытие останавливают плеер, удаляют `src` и освобождают загрузку.
  Портретные видео помещаются целиком; нативные controls не обрезаются.
- GIF в стенде использует статичный WebP; оригинальный GIF стенда сохранён.
  Production использует существующий генератор статичных WebP-превью. Конвейер
  загрузки/сжатия исходных файлов не менялся (его прежние настройки сохраняются).
- Декоративная ручка `.sheet__grip` остаётся компактным `<div>` без перехвата
  фокуса и без растяжения шапки нижнего пульта; закрытие и возврат фокуса
  управляются штатным `overlay-controller.js`. Компактная геометрия Studio
  сохранена на телефонах без искажений от `hover: none` и `pointer: coarse`.
- CSP, серверная авторизация и обработчики медиа не ослаблены. Range использует
  штатный защищённый endpoint с `private, no-cache`; service worker не сохраняет
  API/медиа. Новые публичные assets внесены в allowlist и precache v16.
- Серверные кодеки, CDN, runtime-пакеты, polling/animation loops не добавлялись.
  FFmpeg использовался только вне приложения для генерации маленьких тестовых
  файлов; для запуска приложения и тестов он не нужен.

Два skip — physical-keyboard сценарий на телефоне и CDP-touch сценарий на
десктопе; каждый проверен на предназначенном для него проекте.

Браузерные проверки используют настоящий вход, CSP, upload и Go storage в
одноразовом каталоге. Проверено:

- MP4/H.264 и WebM/VP8, включая вертикальное видео, реально воспроизводятся;
- 0 запросов видео до нажатия; очистка плеера при смене вкладки и закрытии;
- Range возвращает 206 и запрошенные 64 байта; без сессии — 401; API не в SW cache;
- повреждённое видео даёт понятную ошибку, не оставляет плеер и не ломает пульт;
- WebP-превью GIF не содержит animation chunk;
- название палитры непустое уже при первом добавлении в DOM; центрирование и
  координаты образцов стабильны после выбора; перевод обновляется;
- сворачивание/перезагрузка не прячут create/theme/settings, ARIA и переводы
  соответствуют состоянию; footer показывает VERSION;
- на телефоне сохраняется компактная геометрия Studio (переключатель вида, поле
  поиска, карточки и ручка пульта), прокрутка тела sheet работает нативно,
  закрытие восстанавливает фокус и снимает блокировку прокрутки страницы;
- axe не обнаруживает serious/critical нарушений на входе/библиотеке/настройках;
- существующие сценарии создания, загрузки, переименования, доступа, истории,
  плейлистов, экспорта/импорта, удаления, logout, pagination и offline проходят.

Отдельный браузерный визуальный прогон с настоящими изображениями и видео:
320/360/390/430/760/768/1024/1440px × grid/list × раскрытая/свёрнутая навигация.
Горизонтального overflow и ошибок JS/CSP не обнаружено. Скриншоты desktop,
phone, настроек и плеера просмотрены; найденное обрезание портретного плеера
исправлено и закреплено браузерной проверкой геометрии. Повторный прогон стенда
подтвердил 1/13 ссылок и настоящее on-demand воспроизведение.

## Границы проверки

- Touch проверен настоящим Chromium с эмуляцией телефона и CDP touch input,
  **не на физическом iPhone/Android**. Safari/WebKit локально не запускался;
  проект WebKit сохранён в CI. Это не заявление о кросс-браузерной сертификации.
- Нет сравнительного CPU/RAM/скоростного бенчмарка всего приложения. Проверены
  отсутствие фоновых видеозапросов и cleanup, а не обещание нулевой регрессии
  производительности на любом устройстве.
- Read-only стенд не заменяет production-проверки auth/CSP/upload. В нём
  отсутствуют реальные пользовательские данные; previews работают на фикстурах.
- Результаты старых запусков CI на предыдущих коммитах не подтверждают этот
  перенос. После публикации нужен новый CI на текущем head PR #36; merge не выполнен.
